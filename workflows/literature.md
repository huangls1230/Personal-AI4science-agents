# 文献工作流（人工协调骨架）

本文描述由 Codex 主控的任务流程，不是自动执行器。Search 和 Reading 的 Python 工具及使用方式见 [Search 使用说明](../docs/literature-search.md) 与 [Reading 使用说明](../docs/literature-reading.md)。按任务需要选用 `literature_search`、`literature_reading` 和 `literature_citation`；无需为每次任务调用所有角色。实际工具、模型、访问权限与预算须在运行时分别核实。项目 Python Router 只提供建议，原生委派不自动经过 Python Adapter 或 `BudgetGuard`。

## 任务与上下文

1. 主控与用户界定研究问题、检索范围、时间窗、纳入／排除标准和关键决策；确定数据敏感级别、允许访问的来源、外部传输及输出权限。
2. 以项目 `ResearchTask`／`ExecutionRequest` 为依据记录任务标识、目标、所需能力、输入引用、指定输出位置、执行器及重试信息；子任务只接收当前目标、必要上下文与预算。模型、角色和执行器独立选择，不默认传递完整对话或全部论文。
3. 材料位于 workspace 时，按需提供相对路径和 SHA-256，并使用既有路径及哈希检查。检索或 Zotero 发现的外部来源先记录标识、来源与定位；只有获准导入 workspace 并完成校验后，才能作为 `ArtifactReference`／`EvidenceReference`。不得通过契约文件路径越权引用项目外文件。
4. 独立检索或不同论文阅读可在确有收益时并行；在委派前分配各自独占输出路径，由主控串行审核与合并。涉及同一 Zotero 条目、标签或 Obsidian 笔记的写入不得无协调并发。

## 协作与验收

1. **发现**：Search 返回检索式、来源、时间、候选、去重／筛选依据和不足；无法访问来源时标明缺口。
2. **核验**：Citation 在已授权且可用的馆藏或元数据来源中核对候选身份、重复项和引用字段；无法确认的 DOI、Citation Key 等标记未知，不自行补造。来源间冲突需保留并交主控处理。
3. **阅读**：Reading 仅对已实际取得的材料作分析；分别标注元数据、摘要或全文及证据范围，记录页码、章节、图表等可复查定位。事实、作者结论、代理推断与未验证判断应分开；导师式提问为可选项，不预设用户理解已经通过验证。
4. **汇总**：各角色返回简短摘要、执行状态、证据及产物路径、错误和可获得的用量。主控按需读取原始材料、验证路径及哈希、抽查结论和来源；原文或证据不足时标明限制，不把完成状态视为质量通过。
5. **人工决策**：关键研究结论、对外发布及高风险操作交用户批准；外部馆藏或 vault 的写入须在明确授权和审阅变更后进行。未批准时保留草稿或提案，不自动写入。

每次执行结果应映射到 `ExecutionResult` 的任务标识、执行器、状态、摘要、产物、证据、错误及用量字段。原生对话结果不自动成为经验证的契约对象：由主控或未来的桥接代码完成映射及校验。`completed`、质量验证和人工批准是独立状态；执行失败、访问被拒、缺少材料或来源不可用时报告 `failed`、`blocked` 或 `approval_required`，不得报告虚假成功。未知 token 与成本保持未知；提示词预算不是硬上限。

## Zotero 与 Obsidian 边界

Citation 已实现 Zotero Local API 只读查询、附件元数据、原生引用导出以及 workspace 内阅读卡片关联，实际验证与局限见 [Citation 使用说明](../docs/literature-citation.md)。Reading 的 Zotero 输入桥接和外部 Obsidian vault 读写尚未接入；阅读状态仅生成提案，馆藏写入尚未实现。运行时需核实可用工具、授权与访问范围、敏感数据处理、超时、失败、重试、幂等、冲突与回滚方案。只读查询不代表具有写权限；任何真实副作用不得仅凭角色说明执行。不能确定原操作是否成功时，先检查当前状态，再决定是否重试。

工作区中的阅读卡片、文献清单或笔记草稿应保留来源、检索／访问时间、材料类别、版本和精确定位；如有可用原文，记录其受控引用及哈希。哈希只验证内容一致，不验证文献真实性或结论正确性。保留证据和不确定性，不为节约上下文删除必要原始资料。
