# V0.1 架构与边界

Codex 理解科研目标、选择任务、决定是否委派、验收结果并请求必要的人工批准。Python 项目提供契约、策略和本地工具，不自动替代 Codex 调度科研目标。四个 team 表达专业职责，与执行器、模型没有一对一绑定：同一角色可以选择不同的合格执行路径。

执行请求应明确任务、能力、权限、输入、输出与预算。结果携带执行器身份、状态、证据和用量；未报告的用量保持未知。执行完成、质量验证通过、人工批准是不同的状态。执行器的声明不是实际权限隔离的证明，配置开启也不证明本机有可用的外部服务。

大型材料存于 `workspace/`，只向执行器提供需要的受控文件引用；复核时按需打开原文。外部执行器的结果和网络数据是不可信输入，必须检查来源、文件路径和内容。共享输出应事先指定独占负责人或串行合并。缓存或重试须以任务身份和输入版本为依据，避免重复副作用。

V0.1 不连接真实模型 API、外部 Harness 或 MCP，不承诺 Codex 原生委派可从 Python 自动调用；参见 [Codex 集成](codex-integration.md)。在承诺任务 token 或费用上限时，必须确认执行器本身提供并执行相应限制；无法度量、无法强制或使用量未知时不能声称硬上限成立。脚本本身不是 OS 沙箱，高风险任务和敏感数据的隔离必须由执行环境提供。
